以前查询项目问题时： 你要先判断答案可能藏在哪里，再到代码仓库、Issue、PR、CI 日志和项目文档中逐个搜索。信息找齐以后，还要自己拼出完整结论。​
现在询问 Mch AI ： 你可以直接问「最新 CI 为什么失败」「这个 PR 能不能合并」「登录模块以前为什么这样设计」。对话 Agent 会查找当前代码、GitHub 记录、项目文档和已经确认的研发记忆，必要时再调用 Issue、PR 或 CI Agent，最后给出带引用的回答。​
用户只需要描述问题， 查什么、先查哪里、怎样把结果组合起来，都由对话 Agent 完成。​
多 Agent 协同完成复杂工程判断​
有些问题会同时涉及多个方面。比如判断一个 PR 是否可以合并，需要查看代码改动、Review 意见、失败 CI、关联 Issue 和项目约定，一次简单问答很难覆盖完整。​
这时 Mch AI 会先生成分析计划，用户确认后，再让多个专用 Agent 按任务依赖分别检查。页面会实时展示每个任务的执行状态、分析结果和引用内容；发现信息缺失或结论冲突时，系统还会补充检查，最后汇总成一份合入或发布建议。​
这个亮点体现的是完整任务处理能力： 用户提出一个工程问题，多个 Agent 分工调查，系统给出可以核对的统一结论。​
Agent 先起草，人工确认后再执行​
当用户要求评论 PR、创建 Issue、关闭 Issue 或添加标签时， DevFlow AI 会先生成操作草稿。用户可以检查操作对象、具体内容和风险提示，拥有批准权限的人确认后，系统才会调用 GitHub API。​
执行成功以后，系统保存返回结果；执行失败时，也会记录失败原因。草稿的创建、取消、确认和执行都会留下操作记录，后续可以查到谁确认了什么动作，以及最终执行结果。​
Agent 负责整理内容和提出操作，用户始终保留最终决定权。​
